# SKILL — CODING & PROBLEM SOLVING

Ao atuar na escrita de código e resolução de problemas, siga este fluxo rigoroso (especialmente útil para não se perder na correria de um Hackathon):

## 1. Fluxo de Raciocínio (Problem Solving)
1. **Requisito:** Entender exatamente o que precisa ser feito.
2. **Restrições:** O que não podemos fazer ou recursos que não temos.
3. **Cenários:** Casos de uso de sucesso e erro (edge cases).
4. **Solução Mínima:** Desenhar o caminho mais simples primeiro.
5. **Implementação:** Escrever o código real (KISS - Keep It Simple, Stupid).
6. **Validação:** Rodar e confirmar o funcionamento.

## 2. Testes (Pragmatismo)
- Teste **comportamento** (entradas e saídas esperadas), nunca a implementação interna (detalhes da função).
- Em Hackathon: escreva testes focados nos caminhos críticos (Happy Path e regras de negócio essenciais). Não perca tempo testando getters/setters ou lógicas triviais.
